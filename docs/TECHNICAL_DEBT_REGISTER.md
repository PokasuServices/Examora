| TD-R01                              | `next build` failed on `/404`/`/_not-found` with `Error: <Html> should not be imported outside of pages/_document` (or, intermittently, `TypeError: Cannot read properties of null (reading 'useContext')`). Root cause: `apps/web`/`apps/admin`'s `build`/`dev`/`start` scripts wrapped Next.js commands in `dotenv -e ../../.env --` to load the shared root `.env`, which contained `NODE_ENV=development`. dotenv-cli injected that into the child process _before_ Next.js's own bootstrap ran, so Next's internal `process.env.NODE_ENV \|\| "production"` default-setting logic never fired — the entire production build then ran with `NODE_ENV=development`, causing a mismatch between Next's production-compiled internals (`pages.runtime.prod.js`) and the development build of `react-dom-server.edge.development.js`, which trips an internal cross-realm sanity check. Confirmed by reproducing with a bare-minimum page (still failed), ruling out tsconfig/React-version/pnpm-hoisting, then fixing by removing `NODE_ENV` from the shared `.env`/`.env.example` (dev/build/test tools each set their own) and removing the equivalent global `NODE_ENV: test` from `.github/workflows/ci.yml`. | `.env`, `.env.example`, `.github/workflows/ci.yml`    | Fixed 2026-07-18: `NODE_ENV` removed from all shared/dotenv-loaded env sources; `next build` verified green with `NODE_ENV` unset                                                                                                                                                                                                    |
